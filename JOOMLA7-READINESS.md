# Joomla 7 Readiness

> **Scope:** getting Cybersalt extensions ready for Joomla 7 **while Joomla 6 is current**. Joomla 7.0
> isn't out (target 11 Oct 2027, per the joomla-cms milestone), so this file covers only what is
> already certain: everything Joomla 6 marks "will be removed in 7.0", and how to prove an extension
> doesn't lean on the Backward Compatibility plugins. New Joomla 7 APIs and requirements go in a
> `JOOMLA7-CHECKLIST.md` once there is an alpha to read.
>
> Planning, dates, supplier status and the per-extension tracker live in the vault:
> `04.knowledge/joomla-7-migration.md`.

## Why start now

Joomla 7 removes what Joomla 4 to 6 deprecated, and the "Behaviour - Backward Compatibility 6"
plugin that keeps old code alive on Joomla 6 goes with it. Code that runs on Joomla 6 **with compat
and compat6 switched off** is code that won't need an emergency release in October 2027. Every
release from now on should meet that bar, so nothing piles up.

## The rule for every release (from 2026-11-13)

1. **Static scan** with `tools/compat-scan.php` against the oldest and newest Joomla you support.
   Fix every `COMPAT-ONLY`, `NOT FOUND`, `LEGACY` and `ASSET` line before release. `J7` lines are
   Joomla 7 work: fix them when you touch that file, and keep new code free of them.
2. **Prove it on a site** (below) on Joomla 5.4.x and 6.x with both compat plugins off.
3. Say so in the changelog the first time: *"Works with Joomla's Backward Compatibility plugins
   switched off, on Joomla 5 and Joomla 6."*

```
php tools/compat-scan.php /path/to/joomla-5.4 path/to/extension/admin path/to/extension/site ...
php tools/compat-scan.php /path/to/joomla-6.x path/to/extension/admin path/to/extension/site ...
```

The scanner strips comments, resolves every `Joomla\...` class against the real tree (core,
framework packages under `libraries/vendor/joomla/`, core components), and knows every class name
the compat plugins supply on that Joomla. Exit code 0 means clean.

## Prove it on a site

On a throwaway Joomla 5.4.x and 6.x (never a live or demo site):

1. Disable both plugins: *System → Plugins → "Behaviour - Backward Compatibility"* and *"… 6"*, or
   `UPDATE #__extensions SET enabled=0 WHERE folder='behaviour' AND element IN ('compat','compat6');`
2. Turn on `public $log_deprecated = true;` in `configuration.php`; Joomla then writes
   `administrator/logs/deprecated.php`.
3. Install the release zip, upgrade from the previous release, uninstall, reinstall. Open every
   admin screen and every front-end view; call every API endpoint the extension has.
4. Pass when the PHP error log is empty and nothing fatal or `Class "…" not found` shows. The
   deprecation log will still list Joomla 7 items: those are the `J7` work, not failures.

**Sandbox traps met doing this (2026-11-13):**
- **Third-party extensions fail first.** A VirtueMart plugin that still `extends JPlugin`, and
  VirtueMart's config helper calling `JFactory`, took down the CLI and the whole `/api` app the moment
  compat was off. Disable such extensions on the test site; on a client site, compat stays on until
  every extension there passes.
- **Joomla's CLI breaks when `live_site` is set** (`Uri` reads `HTTP_HOST`, which CLI doesn't have).
  Blank it around `cli/joomla.php extension:install` runs.
- **A leftover `installation/` folder** makes Joomla think it isn't installed, on CLI and web alike.
- **`php -S` doesn't route `/api/index.php/v1/...`** without a router that sets `PATH_INFO`
  (see `E:\tmp\mysql8-sandbox\router.php`). Without it the request falls through to the front end.
- `php -S` on Windows serves one request at a time, so it can't reproduce race conditions.

## What Joomla 6 already says goes in 7.0

`JOOMLA7-REMOVALS-6.2.md` is the full list (468 declarations from a Joomla 6.2.0 tree, with
Joomla's own replacement text), generated by `tools/j7-removals.py`. Regenerate it from every new
6.x release. The ones extension code actually hits:

| Removed in 7.0 | Use instead | Safe back to |
|---|---|---|
| `Factory::getDbo()` / `getUser()` / `getLanguage()` / `getDocument()` / `getSession()` / `getMailer()` / `getCache()` / `getConfig()` | `Factory::getContainer()->get(DatabaseInterface::class)`, `$app->getIdentity()`, `$app->getLanguage()`, `$app->getDocument()`, `$app->getSession()`, the mailer factory, the cache controller factory, `$app->getConfig()` / `$app->get()` | J4 |
| `$app->input` (magic property) | `$app->getInput()`. A controller's own `$this->input` is fine. | J4 |
| `$db->getQuery(true)` | `$db->createQuery()`. Removed in **joomla/database 5.0**; Joomla 6.2 ships 4.0, so the timing depends on which database package Joomla 7 ships. | J4 (database 2.2+) |
| `$model->getDbo()` / `setDbo()`, `$table->getDbo()` | `getDatabase()` / `setDatabase()` | J4.3 (`Table` checked on 5.4.1: has `DatabaseAwareTrait`) |
| `$app->getCfg()` | `$app->get()` | J4 |
| `$app->getRouter()`, `ApiApplication::getApiRouter()` | inject it, or `Factory::getContainer()->get(...)` | J4 |
| `HTMLHelper::script()` / `stylesheet()` (and `HTMLHelper::_('script', …)`) | the Web Asset Manager: `useScript()` / `registerAndUseScript()` | J4 |
| `HTMLHelper::register()` / `addIncludePath()` | the service registry | J4 |
| `CMSObject` | `\stdClass` or `Joomla\Registry\Registry` | any |
| **Plugins without `SubscriberInterface`** (methods named after events, e.g. `onContentPrepare($context, &$article)`) | implement `SubscriberInterface` and read the event object. `CMSPlugin::registerLegacyListener()`, `$allowLegacyListeners` and 62 events' legacy argument order all go. | J4 |
| `$this->app` / `$this->db` auto-filled in a plugin | `$this->getApplication()` / `$this->getDatabase()` | J4.2 |
| `Joomla\CMS\Filesystem\*`, `Joomla\CMS\Input\*`, `Joomla\CMS\Application\CLI*`, `BaseApplication`, `CliApplication` | `Joomla\Filesystem\*` (or PHP), `Joomla\Input\*`, Symfony Console | on Joomla 6 these exist **only** through compat6 already |
| the 469 `J*` / pre-namespace helper aliases | the namespaced class | compat6 has them **off** by default on Joomla 6 |

`tools/compat-scan.php` flags all of these as `J7` lines.
